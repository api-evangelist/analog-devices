# Analog Devices

> Analog Devices (ADI) is a global semiconductor company designing high-performance analog,
> mixed-signal and digital signal processing integrated circuits. Its developer surface is
> embedded software, not a hosted web API: cross-platform C/Python libraries that drive ADI
> silicon (libiio, pyadi-iio, no-OS), a VS Code-based IDE and CLI for ADI microcontrollers
> and DSPs (CodeFusion Studio, cfsutil), and a protobuf contract for the 3D Time-of-Flight
> camera SDK. ADI publishes no OpenAPI, no MCP server and no A2A agent card; it does publish
> its own Agent Skills and its own llms.txt for LTspice.

Generated by API Evangelist from apis.yml and the artifacts in this repository.
Provider-published: ADI's own llms.txt lives at https://analogdevicesinc.github.io/ltspice-reference/llms.txt

## APIs

- [libiio](https://analogdevicesinc.github.io/libiio/main/): Cross-platform C/C++ library for Linux Industrial I/O devices — ADCs, DACs, RF transceivers — over local, USB and network (iiod) transports. Python, C# and C++ bindings.
- [PyADI-IIO](https://analogdevicesinc.github.io/pyadi-iio/): Device-specific Python interfaces layered on libiio for ADI transceivers, converters and sensors.
- [CodeFusion Studio](https://developer.analog.com/docs/codefusion-studio/latest/): Embedded development environment for ADI MCUs and DSPs — System Planner, code generation, AI model workflows, debug, and the cfsutil CLI.
- [ADI 3D Time-of-Flight SDK](https://github.com/analogdevicesinc/libaditof): Host/camera SDK whose network connection is defined by a published proto3 contract.
- [no-OS](https://github.com/analogdevicesinc/no-OS): Bare-metal C drivers for ADI parts with no operating system.

## Operating rules

- [Authentication](authentication/analog-devices-authentication.yml): myAnalog interactive login, or `CFS_API_KEY` for cfsutil in CI/CD. The libraries themselves need no credentials.
- [Conventions and reversibility](conventions/analog-devices-conventions.yml): every documented write has a named inverse (`catalog restore`, `apikey delete`, `logout`, package uninstall) but ADI states no reversal window for any of them. Direct register writes via `iio_reg` have no published reversal at all.
- [Error codes](errors/analog-devices-error-codes.yml): OK / BUSY / UNREACHABLE / INVALID_ARGUMENT / UNAVAILABLE / GENERIC_ERROR, plus negative errno from libiio.
- [Packages](packages/analog-devices-packages.yml): PyPI, the Visual Studio Marketplace and GitHub Releases. pylibiio on PyPI is two API generations behind the documented libiio.
- [Lifecycle](lifecycle/analog-devices-lifecycle.yml): semver per project, no status page, no deprecation policy.
